## บทพูดย่อ

1. **ชื่อโปรเจกต์** – "โปรเจกต์ของเราคือการตรวจจับและจำแนกสินค้าร้านค้าปลีก 110 ชนิด โดยเทียบ YOLOv8 สองขนาด"
2. **ปัญหา** – "ร้านค้าต้องระบุสินค้าทีละชิ้นทั้งวัน บาร์โค้ดต้องหาและหันให้ตรง ถ้ากล้องธรรมดาบอกได้ว่าเป็นสินค้าอะไรก็ทำ self-checkout ได้
   คำถามคือโมเดลเล็กพอไหม และควรใช้ตัวเล็ก (n) หรือตัวใหญ่กว่า (s)"
3. **ข้อมูล** – "ใช้ dataset Sell Products จาก Roboflow 13,557 รูป 110 คลาส เกือบทุกรูปเป็นสินค้าชิ้นเดียวถ่ายใกล้ ๆ
   คลาสไม่สมดุลเล็กน้อย มากสุดต่อน้อยสุด 3.3 เท่า"
4. **ขั้นตอน** – "เริ่มจาก weights ของ COCO แล้ว fine-tune 25 epoch ด้วยค่าเดียวกันทั้งสองโมเดลเพื่อให้เทียบกันได้
   loss ของ train กับ valid ลดลงไปด้วยกัน ไม่มีสัญญาณ overfitting"
5. **ตัวชี้วัด** – "ตัวหลักคือ mAP ของงาน detection และเพราะรูปมีสินค้าชิ้นเดียว เราแปลงเป็นงานจำแนกระดับรูปเพื่อรายงาน accuracy กับ AUC ด้วย
   และวัดความเร็วต่อรูป"
6. **ผล** – "ทั้งสองโมเดลได้ mAP@0.5 ประมาณ 0.98 และทายถูก 566 จาก 567 รูปเหมือนกัน ตัว s กรอบแนบกว่าเล็กน้อย +0.76 จุด
   แต่ช้ากว่าเกือบ 2 เท่าบน GPU และเกือบ 3 เท่าบน CPU"
7. **กราฟ** – "confusion matrix ที่ confidence 0.25 ไม่มีช่องนอกแนวทแยงเลย คือไม่ทายสลับคลาสแม้สินค้าแบรนด์เดียวกันต่างรส"
8. **วิเคราะห์** – "รูปเดียวที่ผิดคือหาไม่เจอ ไม่ใช่ทายผิดชนิด และเมื่อเปิดดู 9 กล่องที่พลาด พบว่า 8 กล่องเป็น label ที่ผิดใน dataset เอง
   เช่น กล่องเป็นจุดเล็ก ๆ หรือกล่องซ้ำ"
9. **Prototype** – "เรานำ YOLOv8n ไปรันในเว็บเบราว์เซอร์โดยตรง ไม่มี server รูปไม่ออกจากเครื่อง อัปโหลดรูปหรือถ่ายจากกล้องแล้วได้กรอบกับรายการสินค้าทันที
   และเพิ่มหน้าเฝ้าชั้นวาง ที่หาช่องสินค้าให้อัตโนมัติแล้วเตือนเมื่อช่องไหนของหมด โดยใช้ model ตัวที่สองที่เทรนบนภาพชั้นวางจริง"
10. **สรุป** – "โมเดลตอบโจทย์การระบุสินค้าทีละชิ้น ผลใกล้เคียง baseline ของ Roboflow แต่ไม่ได้ดีกว่า เราเลือก YOLOv8n เพราะแม่นเท่ากันในระดับรูปแต่เร็วกว่า

## สาธิตสดหน้าเฝ้าชั้นวาง (~1 นาที ในสไลด์ 9)

**ก่อนเข้าห้อง**
- เปิด <https://toonrz.github.io/retail-shelf-web/#watch> ใน Chrome ทิ้งไว้ก่อน model ต้องโหลด ~56 MB · pill มุมขวาล่างต้องขึ้น **WebGPU** (ถ้าขึ้น WASM จะช้ากว่ามาก)
- ใช้คลิปชั้นวางสังเคราะห์ที่ซ้อมแล้ว จดไว้ว่าช่องไหนของหมดวินาทีที่เท่าไร และควรเตือนตอนไหน
- ความมั่นใจขั้นต่ำ **0.25** (ค่าเริ่มต้น) · เตือนเมื่อว่าง **5–10 วินาที** ให้เห็นการเตือนเร็ว · วิธีตรวจ: ภาพเต็ม (ค่าเริ่มต้น) · เปิด "แสดงการทำงานของ agent" · เปิดเสียง
- ซ้อมให้จบหนึ่งรอบบนเครื่องที่จะใช้จริง

**ลำดับและบทพูด**
1. ลากคลิปมาวาง → เว็บหาช่องเอง – "ตอนชั้นเต็ม เว็บส่งภาพเต็มให้ทั้งสอง model หาสินค้าทุกชิ้น แล้ว crop ทีละชิ้นให้ model 110 คลาสตั้งชื่อ สินค้าชนิดเดียวกันที่ติดกันรวมเป็นหนึ่งช่อง"
2. ชี้ตารางชื่อช่อง – "ชื่อมาจาก model 110 คลาส แก้ชื่อหรือลากเพิ่มช่องเองได้"
3. กด **เริ่มเฝ้า** → ชี้แถบ "Agent กำลัง…" – "ทุกรอบส่งภาพเต็มให้ model ชั้นวางหนึ่งครั้ง ช่องที่ไม่ชัดค่อย crop ไปยืนยัน กรอบส้มคือส่วนที่ crop · ทั้งหมดรันในเบราว์เซอร์ ไม่มี server"
4. ช่องว่าง → สถานะเป็น "ว่าง x/10 วิ" – "ต้องว่างต่อเนื่องครบเวลาที่ตั้งก่อน กันเตือนผิดตอนมีคนหยิบหรือบัง"
5. ครบเวลา → "ของหมด" สีแดง + เสียง + รายการเตือน – "ผลช้ากว่าภาพราวหนึ่งรอบ มุมภาพบอกไว้ว่าช้ากี่วินาที"

**ถ้ามีปัญหาตอนสาธิต**: หาช่องไม่เจอ → กด "หาช่องอัตโนมัติ" ซ้ำ หรือลากกรอบเอง · เว็บช้า → เช็คว่าเป็น WebGPU · ไม่มีเน็ต → ใช้ screenshot / วิดีโอที่อัดหน้าจอไว้

## คำถามที่อาจถูกถาม

* **ทำไม accuracy สูงขนาดนี้?** ข้อมูลง่าย (ชิ้นเดียว กล่องใหญ่) และ test มีเฟรมติดกันกับ train (ข้อ 7.7 ใน README)
* **Accuracy/AUC ของ detection คิดอย่างไร?** แปลงเป็นระดับรูป: label = คลาสที่มีกล่องมากสุด, คำทำนาย = กล่องที่ conf สูงสุด ≥ 0.25 (ข้อ 6.2)
* **ต่าง 0.76 pp มีนัยสำคัญไหม?** ทดสอบแบบจับคู่ 110 คลาส Wilcoxon p = 0.0013 แต่ 5 คลาสให้ส่วนต่างเกือบ 2 ใน 3 และเทรน seed เดียว
* **ใช้กับชั้นวางจริงได้ไหม?** ยังสรุปไม่ได้ dataset มีรูปหลายชิ้นจริงใน test แค่รูปเดียว · หน้าเฝ้าชั้นวางใช้ shelf model แยก ทดสอบกับวิดีโอชั้นวางสังเคราะห์แล้ว (ถูก 99.1% ราย slot) แต่ยังไม่ได้ลองกับชั้นวางจริง
* **ทำไมไม่เทียบ paper?** ไม่มี paper ที่ใช้ dataset นี้ จึงเทียบกับโมเดลที่ Roboflow เทรนไว้บนหน้า dataset
* **หน้าเฝ้าชั้นวางทำไมใช้ model อีกตัว?** model 110 คลาสเทรนจากรูปสินค้าชิ้นเดียวเต็มเฟรม บนภาพชั้นวางมุมกว้างเจอสินค้าแค่ 0.3% จึงเทรน YOLOv8n 1 คลาสบน SKU-110K (mAP@0.5 0.927) มาบอกว่ามีของหรือไม่ แล้วใช้ model 110 คลาสแค่ตั้งชื่อจาก crop ทีละชิ้น (README ข้อ 8.3)
* **ตัวเลขของ shelf model เป็นเท่าไร?** SKU-110K test tile: P 0.885, R 0.858, **F1 0.871**, mAP@0.5 0.927, mAP@0.5:0.95 0.588 · ราย slot บนวิดีโอสังเคราะห์: ถูก 99.1%, F1 ของการบอกว่าช่องว่าง 0.990 · เตือนครบ 6/6 ช่อง ไม่มีเตือนผิด ช้ากว่าที่ควร 2.5–21.5 วินาที (README ข้อ 8.3)
* **เว็บส่งภาพให้ model ยังไง ส่งทั้งภาพไหม?** ส่งภาพเต็มก่อนทุกรอบ แล้ว crop เฉพาะช่องที่ไม่ชัด (ไม่เกิน 2 ช่องต่อรอบ) เพราะ model รับ 640×640 สินค้าชิ้นเล็กในภาพใหญ่จะเหลือไม่กี่พิกเซล crop ช่วยให้เห็นชัดขึ้น
* **web กับ agent คุยกันผ่าน API อะไร?** ไม่มี server / HTTP API · agent เป็นไฟล์ JavaScript ที่เว็บโหลดมา แล้วเรียกฟังก์ชัน `detect(ภาพ, ตัวเลือก)` ได้กล่อง `{cls, conf, xyxy}` กลับมา ภาพไม่ออกจากเครื่อง · โหลดจาก network แค่ตอนเริ่ม (model + ตรวจ sha256)
* **agent ตัดสินใจเองไหม?** ไม่ agent แค่ดูภาพแล้วคืนกล่อง การหาช่อง นับเวลา และเตือนของหมด เป็นตรรกะของเว็บ (มี unit test)
* **ทำไมไม่เทรนเพิ่ม?** ตัวเลขบน test ใกล้เพดานแล้ว และสิ่งที่ขาดคือข้อมูลชั้นวางจริงสำหรับวัดผล ไม่ใช่ epoch · ถ้าทำต่อ: เก็บคลิปชั้นวางจริงมาวัดก่อน แบ่ง split ตามชุดภาพ แล้ว fine-tune ด้วยภาพจริง (และ SKU-110K ใช้เชิงพาณิชย์ไม่ได้)
* **ทำไมใช้ v8n ในเว็บ ไม่ใช้ v8s?** v8s ช้ากว่า ~2 เท่า ได้ mAP@0.5:0.95 เพิ่มแค่ 0.76 pp และระดับรูปถูกเท่ากัน
